# Памперс-бот

Telegram-бот хранит персональную память отдельно для каждого собеседника. Долговременная память работает только в одном явно разрешённом групповом чате. В остальных чатах бот сохраняет прежнее поведение без чтения и записи этой памяти.

## Настройка

Секреты и настройки можно хранить в локальном `.env`, который уже исключён из контроля версий:

```dotenv
TELEGRAM_BOT_TOKEN=...
GEMINI_API_KEY=...
ALLOWED_CHAT_ID=-1001234567890
MEMORY_DB_PATH=E:\pampers-bot\memory.db
MEMORY_MAX_EPISODES=6
MEMORY_CONTEXT_MESSAGES=6
```

- `ALLOWED_CHAT_ID` — числовой ID единственного чата с долговременной памятью. Значение обязательно заменить на реальное; при пустом или неверном значении память отключается везде.
- `MEMORY_DB_PATH` — путь к SQLite-базе, по умолчанию `memory.db` рядом с ботом.
- `MEMORY_MAX_EPISODES` — максимум подходящих прошлых эпизодов в одном запросе, по умолчанию `6`.
- `MEMORY_CONTEXT_MESSAGES` — максимум недавних сообщений этого пользователя в контексте, по умолчанию `6`.

Числовой ID группы можно взять из уже существующего журнала обработчика сообщений. Если он там не выводится, временно залогируйте только `message.chat.id` в обработчике и отправьте в группу одно сообщение. Токен бота выводить нельзя. У групп и супергрупп ID обычно отрицательный; копируйте его целиком.

## Импорт архива

Команды запускаются в PowerShell из `E:\pampers-bot`:

```powershell
$env:ALLOWED_CHAT_ID='-1001234567890'
.\venv\Scripts\python.exe import_history.py 'E:\ЧАт\ChatExport_2026-08-13' --db '.\memory.db' --dry-run
.\venv\Scripts\python.exe import_history.py 'E:\ЧАт\ChatExport_2026-08-13' --db '.\memory.db' --no-summarize
.\venv\Scripts\python.exe import_history.py 'E:\ЧАт\ChatExport_2026-08-13' --db '.\memory.db' --status
.\venv\Scripts\python.exe import_history.py 'E:\ЧАт\ChatExport_2026-08-13' --db '.\memory.db' --resume
# Только после проверки оценки, если она больше 100:
.\venv\Scripts\python.exe import_history.py 'E:\ЧАт\ChatExport_2026-08-13' --db '.\memory.db' --resume --allow-over-budget
```

`--dry-run` только считает данные и не создаёт базу. `--no-summarize` безопасно импортирует исходные сообщения и эпизоды без обращения к Gemini. `--status` ничего не изменяет и отдельно показывает `episode_summary_requests` (пакеты по 20 эпизодов), `relationship_summary_requests` (полные блоки по 10 эпизодов для каждого пользователя) и их сумму `estimated_requests`. При оценке сводок отношений ожидающие и ошибочные эпизоды считаются потенциально готовыми после обработки.

Обычный запуск и `--resume` автоматически останавливаются до создания клиента Gemini, если суммарная оценка больше 100 внешних вызовов. После проверки `--status` оператор может явно разрешить такой запуск флагом `--allow-over-budget`. Исходные данные при этом можно безопасно импортировать до проверки лимита: повторный импорт идемпотентен.

Повторный импорт безопасен: уже сохранённые сообщения и эпизоды не дублируются.

## Проверка и запуск

Бот использует агрегированный стиль 181 ответа Памперса2004. В каждый адресный запрос добавляется условие: только прямой наезд на Памперса/Диму делает ответ примерно на 30% жёстче; цитаты, пересказы, обсуждение кода или фильмов и неоднозначные сообщения остаются нейтральными. Это выполняется в том же единственном запросе к Gemini.

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe startup_check.py
.\venv\Scripts\python.exe startup_check.py --online
.\venv\Scripts\python.exe bot.py
```

`startup_check.py` выполняет локальную проверку без запуска Telegram polling: проверяет числовой `ALLOWED_CHAT_ID`, состояние `memory.db` и количество оставшихся запросов импорта. В отчёт попадают только счётчики и названия классов ошибок, но не токены, пути или тексты внешних ошибок.

`startup_check.py --online` переходит к внешней проверке только после успешной локальной: вызывает Telegram `getMe` и делает один короткий запрос здоровья к Gemini. Он не читает обновления и не отправляет сообщения в чат. Запускайте `bot.py` только если выбранная проверка завершилась с кодом `0`.

База переживает перезапуск. Не копируйте `memory.db` в публичные репозитории: она содержит историю разговоров.
